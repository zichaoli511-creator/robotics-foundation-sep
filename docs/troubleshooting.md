# 踩坑与收获

这些问题发生在搭建 WSL 环境、使用 Git 和编写六关节项目的过程中。记录的是**判断线索与学到的概念**，不是通用安装教程。

| 情况 | 当时的判断 | 学到的东西 |
| --- | --- | --- |
| Windows 找不到刚安装的 Ubuntu | WSL 发行版仍可从终端启动 | 应区分应用菜单显示与发行版是否真正安装 |
| WSL 报 localhost 代理警告 | 软件源更新成功，警告没有阻断当前工作 | 先验证实际网络访问，再处理代理配置 |
| VS Code 终端显示 `PS` | 打开的是 PowerShell，代码实际运行环境是 Ubuntu Bash | 看提示符和当前路径，确认命令在哪个系统执行 |
| Windows 路径无法直接用于 Bash | `C:\...` 与 `/mnt/c/...` 是不同写法 | 路径属于执行命令的环境，不能直接照搬 |
| 在 `/mnt/c` 使用 `chmod` 看不到预期变化 | Windows 挂载目录的权限显示与 Linux 家目录不同 | 权限实验应在合适的文件系统中验证 |
| GitHub 页面没有显示本地修改 | 修改尚未完成提交和远程同步 | 工作区、暂存区、本地提交、远程仓库是不同层次 |
| Git 显示大量文件“变动” | 部分变化只是 LF 与 CRLF 换行格式差异 | 查看 diff 后再判断代码是否真的改变 |
| `git fetch` 被 `Ctrl+Z` 暂停 | 进程仍留在终端作业列表中 | `Ctrl+Z` 是暂停，`Ctrl+C` 才是终止当前命令 |

最有用的习惯是：先观察**当前目录、终端类型、报错原文和文件 diff**，再决定下一步。它减少了把环境问题误判为代码问题的情况。
